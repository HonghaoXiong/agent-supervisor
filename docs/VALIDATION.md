# 验证与迁移验收

## 离线回归

```bash
python -m pip install -e .
python -m unittest discover -s tests -v
```

CI 矩阵为 macOS/Linux × Python 3.11/3.13，不发送模型任务、不使用真实账户、不提交集群任务。离线通过能验证适配器逻辑，不能验证目标机器的 ZCode 登录、模型服务或权限实现。

原开发适配器曾在 macOS 上完成真实允许、拒绝、同会话续接以及一次小型远程提交/回收；该历史结果不替代移植版本或另一台机器的验收。历史项目日志、服务器信息和源程序未随本仓库分发。

## 每台新机器的验收顺序

1. 独立安装并登录 ZCode，确认其正常工作。
2. 安装本包、生成本机配置，运行 `czs doctor`。确认受支持的 bundle 指纹，不能跳过未知版本检查。
3. 运行 `czs probe`，确认原生协议会话能启动并干净退出。
4. 执行初始化生成的报告任务，核对 Write/Edit 审批、实际文件变化和成功终态。
5. 在新的小型副本中执行一条经过审查的本地测试命令，检查匹配的 Bash 审批、退出元数据和原始测试结果。
6. 用另一个无害任务验证越界写入请求被拒绝，文件确实未产生；预期拒绝的任务应被判交付失败，而非伪装通过。
7. 续接本桥接登记的同一会话，使用新合同及新输出名，确认工作副本与会话身份一致。
8. 若需要集群，再单独验收固定资源上限的提交和回收执行器。

保留版本、运行时间、源码/输入哈希、完整命令、审批事件、工具结果和文件差异。不要把 worker 自述当作执行证明。

## 判定失败的情况

版本/哈希不匹配、审批缺失、会话或工具身份不匹配、命令非零退出或超时、冻结输入变化、输出证据缺失都应拒收。审批系统拒绝请求是有效控制证据，却不表示原任务已经完成。

`delivery_ok=true` 之后，Codex 仍需审查内容是否满足需求。科学公式、数据交换语义、守恒、收敛与长期稳定性等领域判据应另列在任务验收合同中，本工具不替代这些判据。
